## One command, one review report

From the repository root with Python 3.12 and Node:

```bash
python tools/review_project.py
```

Open **outputs/review/index.html**. Its machine-readable companion is **outputs/review/review.json**. The runner reconstructs the three-fold synthetic temporal example and verifies its six committed artifacts exactly. It also loads the frozen models in fresh isolated processes and checks all 198 response rows without refitting. Fifteen checks cover those learning/delivery contracts, current source-readiness contracts, evidence-bundle acceptance and rejection, historical receipt arithmetic, recovery, aggregate boundaries, owner replay/storage accounting, execution history, qualification frontier and controls, exact bracket calculations, actual demo handlers and deterministic offline packaging. A failed check makes the review fail and retains its log. Invalid aggregate contracts or mismatched committed synthetic artifacts fail before the report is issued. Evidence-bundle fixtures are not an audit of an actual CI run; that is a separate command using actual archived bytes and trusted bindings.

## Audit the execution, not just its summary

The [evidence verifier](evidence_bundle.md) closes a concrete retention gap: an earlier runtime receipt referred to a five-cell executed notebook whose generated bytes were missing from the downloadable CI evidence. Retention now includes that notebook and figure, while the verifier follows each declared canonical and nested dependency to an exact body. Source trees, run identities and file sets must agree. Missing, altered, unsafe, duplicate or cross-run evidence is rejected.

This is deliberately an **offline reader**, not an executor of downloaded Python or notebooks. A separate expected binding is the trust anchor; an internally consistent archive is not a signature or proof of authorship. The publication does not broaden access to private competition methods, forecasts or source banks.

No credentials, source download, private model artifact or Python package installation is needed. Frozen synthetic model artifacts are committed publicly. Optional notebook regeneration uses the project's locked development environment. The browser demo still packages exactly five reviewed static source files.

## A recovery contract that runs

The public reliability example is written independently from the private research runner. Four synthetic observations deliberately include an eligible timestamp, a late timestamp, an unknown timestamp and a second eligible timestamp.

| Invocation | Qualification calls | Result |
|---|---:|---|
| Uninterrupted cold run | 4 | All units committed |
| Deliberate stop after one unit | 1 | One result retained |
| Resume | 3 | The committed unit is verified and reused |
| Warm repeat | 0 | All four results reused; fingerprints and hashes still checked |

A spy test counts actual calls to qualification; the counter is not merely a count of new file writes. Cold and resumed results must match. Changing an input or corrupting committed content raises an integrity error. Duplicate identities are rejected before writes, a second invocation cannot take an active lock, symlink checkpoints are rejected, and unknown timing stays unknown.

Writes use a temporary file, file synchronization and atomic replacement. These are focused recovery checks, not a claim of a distributed transactional system or protection against a malicious actor who controls both content and its hashes.
